# MedOrbits Project Knowledge

## Operating rules
- Inspect existing files before proposing edits.
- Preserve the existing repository architecture.
- Keep changes minimal and explain their purpose.
- Never expose credentials, API keys, or private documents.
- Never commit, push, merge, or deploy automatically.
- Require explicit approval before writing project changes.
- Run relevant checks after approved changes.
- Never claim a test passed unless it actually ran.
- Preserve existing working routes and asset paths.
- Follow established MedOrbits design rules and responsive layouts.

## Learning process
Document confirmed architecture, successful fixes, failed approaches,
and durable project decisions here or in DECISIONS.md.
Do not store secrets or personal data.
